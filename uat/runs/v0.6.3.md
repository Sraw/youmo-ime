## 设备 UAT 的失败和重跑

### 失败（改用例前）和用户的决定

| 编号 | 结果 | 看到的 |
|---|---|---|
| VO-54 [P1] | **失败**（debug 包，5556 上两次、新起的 5556 上一次，三次一样） | 手动加词「徐竫」（xu jing）后说「麻烦你去找一下徐婧」（`xujing` 片段，和 VO-38 同一段），框里是「麻烦你去找一下徐静」，没有换成用户的「徐竫」。v0.6.2 debug 包（`2026-11-18-emulator-0.6.2-debug.md`）和 0.6.1 的三次跑都是「徐竫」。同一片段 VO-38（加「徐婧」）照样换成「徐婧」，所以是「竫」这个三级字的词不再被换上。很可能是 4757cf99f（同音换成用户的词改由拼音引擎的语言模型看整句定，用户词加 1.5）带来的：语言模型里「竫」分太低，加分也比不过「徐静」。VO-54 的 .md 和脚本没随那次改动更新。**复现**：debug 包、导入语音包 → 词库与短语 → 用户词库 → 手动添加的词 加「徐竫」拼音 xu jing → 测试页按住空格播 `xujing.wav`（`uat.py run --ids VO-54`）→ 框里「徐静」。要么是回退（用户手动加的生僻字名字不再能用语音打出来），要么改用例；没改 App。 |
| VO-56 [P2] | 失败（按用例字面） | 加用户词「酒店式公寓」后说「九键输入法」：重新生成片段后第一次「9件输入法」，新起的模拟器上「9键输入法」。用例要守的「不被听成『酒店…』」没出现；失败是因为脚本要「九键」，而数字由整理模型写成「9」（0.6.1 debug 跑时同样是「9键输入法」、同样判失败，一直没改）。另外 `jiujian` 片段本身 X-ASR 单独听也是「九件」。算用例预期过时，不是 App 问题；要不要接受「9键」写法由用户定（语音数字写法只由整理模型定）。 |

**用户决定（11-24）和改用例后的结果**（`2026-11-24-emulator-0.6.2-49-g5595336f5-voice-followup.md`）：
- VO-54 改成这样：先说，框里是「徐静」这类而不是「徐竫」；然后删掉重打「徐竫」，提示条问「以后总是把『徐静』写成『徐竫』？」，点 **总是换**，再说就是「徐竫」。屏蔽三级字那一半不变。代码里查过：屏蔽优先于总是换，`VoiceEngine.userHotwords` 先 `VoiceHotwords.unheld(all, held)` 把含挡掉的字的用户词拿掉，再 `voiceHomophones(w)`，所以标了总是换的「徐竫」也进不去。重跑**通过**：第一次「麻烦你去找一下徐静」；重打后问「以后总是把『徐静』写成『徐竫』？」；点总是换后是「麻烦你去找一下徐竫」；屏蔽三级字后是「麻烦你去找一下徐静」。
- VO-56 的预期改成：框里没有「酒店」，「九键」「9键」都算通过。重跑**通过**，框里「9键输入法」。VO-38、VO-59 是相邻的用例，一起重跑，都通过。
